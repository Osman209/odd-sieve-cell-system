Fix the rendering failures on the published pages

The rendering checker had never actually run.  check_github_math.js takes its
files from the command line; it was always invoked with none, so it looped over
an empty list and reported zero problems.  Run as the README says, against what
had just been pushed, it reported 45.

Three failure modes, all now fixed and all now checked for:

GitHub strips the backslash from escaped ASCII punctuation inside math.  Fifty-one
sites: \, became a comma (this is why $H\,w_H$ printed as "H,w_H" on the page),
\% became % and opened a comment that swallowed the rest of the formula, \# became
a reserved character, \\[2pt] inside cases became an undefined control sequence,
and \! and one raw < were removed.

Display math inside a blockquote is not treated as math: Theorem 1 of Paper 6
printed as raw source with the underscores of }_{ eaten by markdown emphasis.  All
62 such sites are now inline $\displaystyle ...$, which renders reliably there.

Two math spans separated by one punctuation character merge into one: $10^4$-$10^5$
broke a table cell.  Eleven sites merged into single spans.

Unbraced fraction arguments are braced, since an unbraced argument is the shape
that breaks when a brace vanishes.

check_github_math.js now refuses to run with no files and exits 2, and gains checks
for display math in a blockquote, adjacent spans, and a space before a closing $.
All three were confirmed to fire against injected defects.  Full run: 0 problems.

Verified: audit.py clean, all nine verification scripts exit 0, site and PDFs
rebuilt.
